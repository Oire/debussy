Lens: does the change do what the plan asked?

Read the plan's Overview and Done when first, then check the code against them: requirements that are missing or only half done, an approach that fails under conditions the plan implies, and pieces that exist but are never wired in (a handler nobody registers, a setting nothing reads, a migration that is not run, an interface with no implementation). Follow the data from input to output and check each step on the way.

Style is out of scope for this lens.
